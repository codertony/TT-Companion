# Spec Delta

## Purpose

定义产品七能力域与「内容与规则治理」横切域的组织边界，以及各核心功能模块（今日决策台、评估中心、计划中心、训练执行器、动作库、洞察、设置）与四 Tab 导航职责，为评估、处方、执行、验证、洞察提供顶层产品结构。

## ADDED Requirements

### Requirement: 七能力域划分

系统 SHALL 将产品组织为七个能力域，每个能力域回答一个明确的用户问题并产出对应的核心产物。

#### Scenario: 能力域与核心产物可追溯

- **WHEN** 系统描述某个产品能力
- **THEN** 该能力归属于「用户目标与约束 / 健康与状态 / 能力评估 / 训练决策 / 训练执行 / 专项验证 / 洞察与复测」之一，并能说明其核心产物（如 `SafetyDecision`、`CapacityProfile`、`TrainingPrescription`、`ValidationResult`）

### Requirement: 内容与规则治理横切域

系统 SHALL 将「内容与规则治理」作为横切能力域，使动作内容与判断规则可版本化、可追溯，而非散落在各功能页面中。

#### Scenario: 动作与规则可追溯

- **WHEN** 一个训练动作或一条安全规则被使用
- **THEN** 系统能指出其协议版本 / 规则版本与证据来源

### Requirement: 首页升级为今日决策台

首页 SHALL 从打卡入口升级为今日决策台，集中呈现今日 readiness、当前瓶颈（最多两个）、本周期 ONE CUE、今日推荐训练与一键开始。

#### Scenario: 今日决策台信息完整

- **WHEN** 用户打开首页
- **THEN** 能看到 readiness（绿/黄/红及原因）、当前瓶颈、本周期 ONE CUE、今日推荐训练（时间/配比/强度）与一键开始入口

#### Scenario: 复测或周末验证任务卡

- **WHEN** 到达复测日或周末球台验证时机
- **THEN** 首页显示对应的复测 / 验证任务卡

### Requirement: 评估中心与计划中心分离

系统 SHALL 将评估中心（健康恢复、心肺、功能力量与控制、活动度与平衡四类）与计划中心（今日训练、周计划、训练周期三尺度）作为独立模块，且每个评估协议须包含适用人群、前置条件、器材、标准流程、单位、有效判定、疼痛处理、左右侧、复测周期与协议版本。

#### Scenario: 评估协议字段完整

- **WHEN** 用户进入某个评估协议
- **THEN** 该协议包含适用人群、前置条件、所需器材、标准流程、单位、有效与无效判定、疼痛处理、左右侧要求、复测周期与协议版本

#### Scenario: 手动调整计划的可见影响

- **WHEN** 用户手动移除或调整计划中的某个动作
- **THEN** 系统展示该调整对处方目标的影响（如「移除单腿稳定后，本周下肢控制训练量将低于处方目标」）

### Requirement: 四 Tab 导航职责重定义

系统 SHALL 保留首页/训练/数据/我的四个底部 Tab，但重新定义为「今天 / 训练 / 进展 / 我的」，分别承载今日决策台、计划与训练入口、五类 Dashboard 与复测复盘、档案与设置。

#### Scenario: 四 Tab 职责明确

- **WHEN** 用户在不同 Tab 间切换
- **THEN** 「今天」展示今日决策台、「训练」展示今日/本周计划与内容库、「进展」展示能力 Dashboard 与球台验证/复测、「我的」承载档案、目标、器材、评估中心与数据管理
