# Spec Delta

## Purpose

定义 V2.0 的分阶段迭代路线（Phase 0–4）、Epic A–F 任务拆分、首个纵向切片、领域不变量、质量测试要求、最小产品指标与非目标边界，作为后续子 change 的分解依据与验收锚点。

## ADDED Requirements

### Requirement: 分阶段迭代路线

系统 SHALL 按 Phase 0（真实性与工程地基）→ Phase 1（首个 Layer 0 纵向切片）→ Phase 2（Layer 0 基础能力中心）→ Phase 3（专项能力评估与真实训练闭环）→ Phase 4（设备与视频能力）的顺序演进。

#### Scenario: 路线可拆解为独立子 change

- **WHEN** 团队推进 V2.0
- **THEN** 每个 Phase 可作为一个或多个独立子 change 落地，互不阻塞既有功能的可用性

### Requirement: Phase 0 真实性与工程地基

系统 SHALL 在 Phase 0 修复 `club` 场景空计划、补真实 PWA 能力或降级文案、实现 JSON 下载/导入/校验/版本迁移、建立统一 Repository 接口、将反应/预判/张力结果纳入统一结果模型、建立训练执行事件与中途恢复、增加主流程 E2E 基线。

#### Scenario: 所有场景可生成计划

- **WHEN** 用户在任意场景下请求生成计划
- **THEN** 能生成计划，或返回明确的「不可生成」原因

#### Scenario: 专项结果关页后可查看

- **WHEN** 用户完成一次反应/预判/张力训练并关闭页面
- **THEN** 该结果被持久化到统一结果模型，之后仍可查看

### Requirement: 首个纵向切片为单腿稳定/下肢控制

系统 SHALL 以「单腿稳定/下肢控制 → 步法稳定」作为首个完整纵向切片，链路为：每日疼痛/疲劳 Check-in → 单腿站 + 单腿坐站评估 → 左右差异与置信度 → 识别下肢稳定候选 limiter → 生成单腿稳定/分腿蹲/启动制动计划 → 周末两点移动验证 → 4–6 周复测。

#### Scenario: 纵向闭环可验证

- **WHEN** 用户走完首个纵向切片
- **THEN** 能看到为什么被判断为 limiter、Yellow 状态时高冲击动作被自动降级、每个动作有退阶/进阶/停止条件、复测使用相同协议、改善后 limiter 可被撤销或降级

### Requirement: Epic 任务拆分

系统 SHALL 将实现工作拆为 Epic A（领域内核）、B（数据与迁移）、C（Readiness 与安全门）、D（单腿稳定纵向切片）、E（处方引擎）、F（统一执行器），并保持现有 UI 可运行、不一次性重写页面。

#### Scenario: Epic 独立可交付

- **WHEN** 实现某个 Epic
- **THEN** 该 Epic 有清晰边界，可在不破坏现有功能的前提下增量交付

### Requirement: 领域不变量

系统 SHALL 维护以下不变量：Red 状态绝不生成训练处方；Yellow 被禁用的冲击动作绝不进入计划；无协议版本的测试结果不参与跨周期比较；派生分数不覆盖原始 Observation；同一导入源记录不重复写入；不完整训练不被记录为完整完成；训练计划可解释到输入数据与规则版本；规则更新不静默篡改历史决策。

#### Scenario: 不变量可被属性测试验证

- **WHEN** 系统在任意输入下生成处方或处理数据
- **THEN** 上述不变量均成立，且可通过属性测试断言

### Requirement: 测试金字塔与浏览器验证

系统 SHALL 覆盖领域单测（安全规则、能力派生、limiter 排序、配比、过滤、剂量）、规则黄金用例、属性测试、数据测试（迁移/去重/幂等/回滚）、组件测试（Check-in、评估、暂停恢复、疼痛退出）、E2E 纵向链路与浏览器验证（移动端、离线、后台切换、深色模式、可访问性）。

#### Scenario: 编译通过不等于正确

- **WHEN** 一个规则或迁移被实现
- **THEN** 需有对应领域单测、黄金用例或属性测试覆盖，而非仅以编译通过作为完成标准

### Requirement: 非目标边界

系统 SHALL 明确不做：疾病诊断与医学风险评分、把所有能力压成单一总分、首版云端多用户、第一阶段接入 HealthKit/Health Connect、评估协议未稳定前的大模型自动处方、复杂摄像头动作识别。

#### Scenario: 不越界诊断

- **WHEN** 系统处理健康相关数据
- **THEN** 不输出疾病诊断或医学风险评分，不把能力结构压成掩盖结构的单一总分

### Requirement: 最终回答五个问题

系统 SHALL 最终稳定回答五个问题：今天是否适合训练、当前真正限制表现的能力是什么、今天为什么练这些、训练过程中发生了什么质量如何、几周后用什么证据判断有效。

#### Scenario: 五问形成可追溯闭环

- **WHEN** 用户使用完整训练周期
- **THEN** 每个问题都能从原始数据、规则版本与训练事件追溯到答案，形成闭环而非孤立打卡
