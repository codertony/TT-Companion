# Design

## Context

Phase 0 / 1 / 2 已分别交付反应、步法、发力链、预判等独立能力。Phase 3 不新增底层机制，而是把这些能力编排成完整击球链路，并加一层「问题 → 专题」映射。动机见 proposal.md - Why。

## Goals / Non-Goals

**Goals:**
- 复用既有 hooks / 动作库，编排成整合训练状态机。
- 让训练推荐从「手动选专题」过渡到「选问题 → 自动推荐」。

**Non-Goals:**
- 不做姿态识别与 AI 诊断（Phase 4）。
- 不做多球真实对练 / 硬件。

## Decisions

### D1：整合训练用「来球状态机」编排，复用既有 hooks
- **选择**：一个 `useIntegration` 状态机串起「出球 → 判断 → 移动 → 稳定 → 发力 → 击球 → 还原」，内部调用 Phase 0/1 的时机化提示与反应刺激。
- **理由**：不重写，只在编排层组合。
- **备选**：为整合单独写全新执行器——重复，放弃。

### D2：来球类型用简单随机（均匀），不做难度自适应
- **选择**：FH/BH × Topspin/Backspin 四类均匀随机；Level 4–7 逐步加方向 / 正反手 / 球路维度。
- **理由**：MVP 可预测、可测；自适应留后续。

### D3：错误→专题映射做成静态数据表，不引入规则引擎
- **选择**：`data/errorDrills.ts` 静态映射（问题 → 专题数组 + Primary Cue），生成器读表推荐。
- **理由**：数据驱动、易扩展，无需新依赖。
- **备选**：AI 推荐——Phase 4 再考虑。

### D4：整合训练的「模拟击球」用影子动作 + 时机化提示，不用视觉判定
- **选择**：提示用户完成对应影子动作，系统只做节奏与 Cue 引导，不判定动作正确性。
- **理由**：动作判定属 Phase 4（姿态识别）。

## Risks / Trade-offs

- [整合链路过长，用户难以一次完成] → 分 Level 递进，Level 4 起逐步加维度。
- [来球随机与 Cue 冲突] → 出球后先给判断 Cue、再给动作 Cue，顺序固定。
- [无动作判定，训练质量难保证] → 明确为「影子演练」，靠时机化提示与用户自评。
