# Design

## Context

Phase 0 已交付动作库、训练执行器与时机化提示机制（`timedPrompts`）。Phase 1 在其上新增发力链 / 张力训练，不引入新框架或后端。动机见 proposal.md - Why。

## Goals / Non-Goals

**Goals:**
- 复用 Phase 0 的 `Exercise.timedPrompts` 机制承载发力链与张力训练，避免新机制。
- 把「稳定—传递—加速」与「非绝对化」固化为可校验的文案约束。

**Non-Goals:**
- 不做姿态识别 / 摄像头（Phase 4）。
- 不做正反手随机整合（Phase 3 的 Power Chain Level 4–7）。

## Decisions

### D1：发力链阶段复用 timedPrompts，而非新渲染引擎
- **选择**：正手六阶段 / 反手四阶段 / 动作链感知模式，都用 `Exercise.timedPrompts`（atSec + type + text）承载；「动作链感知」= 一组按 2～3s 触发的分段提示。
- **理由**：机制已存在且可单测，避免平行实现。
- **备选**：独立的「阶段状态机」——重复且难统一，放弃。

### D2：发力专题界面用「人体简图 + 发光区域」，不用骨骼模型
- **选择**：轻量人体简图，四个发光区域（脚 / 髋 / 躯干 / 手臂），当前训练段高亮；只显示 2～3 条 Cue。
- **理由**：训练中用户无精力读复杂画面，符合「一屏一任务」。
- **备选**：真人照片 / 骨骼模型——重、易过时，放弃。

### D3：张力刻度 0–10 做成独立 UI 组件，标注「松 / 紧」锚点
- **选择**：滑块或分段按钮 + 两端文字锚点（0 完全松、10 最大用力）。
- **理由**：可复用于张力练习与自评。

### D4：发力链动作并入动作库，新增「阶段 / 等级」元数据
- **选择**：`Exercise` 增加可选的 `chainStage`（发力链阶段）与 `level`（Level 0–7）字段，生成器按需使用。
- **理由**：保持单一动作数据源。

## Risks / Trade-offs

- [分段教学被误解为「依次启动 / 各段独立」] → 教学文案始终强调「真实运动是连续协调，分段只为学习角色」。
- [发光区域人体简图插画成本] → 先占位简图，动作正确性优先于美观。
- [张力等级主观] → 明确为「自评工具」，不做客观判定。
