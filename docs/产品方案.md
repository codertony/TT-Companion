# 1. 产品概述

### 1.1 一句话定位

> 把"一周只有周末能上球台"的业余乒乓球爱好者，扩展到**一整周都在进行专项技能学习**——工作日做离台能力训练，周末做真实验证。

### 1.2 要解决的问题

| 约束 | 表现 |
| --- | --- |
| 工作日无球台 | 周一至周五只能等待 |
| 反馈周期长 | 周末发现的技术问题，要等 7 天才能再练 |
| 碎片时间多 | 通勤、办公室零散 1～10 分钟 |
| 无人指导 | 不知道该练什么、一次练多少 |

核心命题：**没有球台的五天里，维持并改善"能打好乒乓球的身体与神经系统"。**

### 1.3 产品边界（明确不做）

- 不是健身 App（不以卡路里 / 步数 / 时长为目标）
- 不是教学视频 App
- MVP 不做：动作识别 / 摄像头 / 姿态估计 / 手表 IMU / AI Coach
- 不做：账号、云同步、社交、排行榜

# 2. 目标用户与场景

### 2.1 用户画像

- 业余乒乓球爱好者；工作日基本无球台，周末 1～3 次真实打球
- 通勤时间长（地铁为主）；无整块训练时间；目标是长期技术提升 + 减少动作退化

### 2.2 核心场景

| 场景 key | 名称 | 空间 | 建议时长 | 适合内容 |
| --- | --- | --- | --- | --- |
| `metro_sit` | 🚇 地铁（坐） | 极小 | 1～5 分钟 | 反应、决策、等长收缩、张力感知 |
| `metro_stand` | 🚇 地铁（站） | 极小 | 1～5 分钟 | 足底感知、踝泵、轻度平衡 |
| `office` | 💼 办公室 | ~1㎡ | 3～10 分钟 | 步法、核心、影子动作 |
| `home` | 🏠 家 | ~2㎡ | 5～20 分钟 | 下肢稳定、启动制动、随机步法、影子挥拍 |
| `club` | 🏓 球馆（周末） | 球台 | — | 验证迁移（仅反馈入口，不生成训练） |

# 3. 核心闭环

```
周末真实打球 → 发现 1 个核心问题 → 形成 ONE CUE
→ 生成工作日碎片训练 → 认知+身体+动作训练
→ 周末再次验证 → 判断是否换 Cue → 循环
```

**关键设计：一次只纠正一个问题。** 每周只有一个 `Primary Cue`，其余进 `Backlog`。

---

# 4. 产品原则

1. **一次一个 Cue** —— 每周只推一个技术目标。
2. **质量优先于疲劳** —— 指标是判断速度、动作质量、稳定度、规律性、周末迁移。
3. **碎片优先** —— 支持 30s / 1 / 3 / 5 / 10 分钟。
4. **场景感知** —— 先选场景再给动作，地铁绝不推大幅移动/挥拍。
5. **移动端优先** —— 单手可操作、一次点击开始、大按钮、离线可用。
6. **本地优先** —— 全部数据存 `localStorage`，无网络依赖。

## F1 场景 + 时长选择

### 7.1.1 用户流程

```
进入「训练」Tab
  → 选择场景（5 选 1）
      ├─ 选 metro → 追加询问「坐着 / 站着」
      └─ 其他场景 → 直接进入下一步
  → 选择时长（1 / 3 / 5 / 10 分钟）
  → 点击「生成训练」→ 进入训练执行页
```

### 7.1.2 场景枚举与可用性

| 场景 | 允许的训练类型 | 禁止 |
| --- | --- | --- |
| metro_sit | reaction, audio, visualize, isometric, tension | 步法、挥拍、站姿平衡 |
| metro_stand | 足底感知、踝泵、轻度平衡、reaction | 快速移动、跳跃、闭眼平衡、挥拍 |
| office | reaction, audio, shadow_footwork, core, shadow_swing | 大幅移动、跳跃 |
| home | 全部类型 | — |
| club | 仅反馈入口 | 不生成训练 |

### 7.1.3 时长档位

1 / 3 / 5 / 10 分钟。训练生成器会按档位填充动作块（见第 9 节）。

### 7.1.4 交互细节

- 场景卡片：大图标 + 名称 + 一句话说明（如"地铁·坐——反应与感知，不影响他人"）。
- 时长按钮：4 个大按钮，选中态高亮。
- "生成训练"按钮固定在底部，场景/时长未选全时置灰。

### 7.1.5 边界与异常

- 首次进入无历史：给默认场景 `home`。
- `club` 场景不进入时长选择，直接跳转周末反馈（F8）。

### 7.1.6 验收标准

- 任意 场景×时长 组合都能生成一份非空训练计划。
- metro 场景生成的计划中不含任何 `space > 0` 或 `intensity: high` 的移动/挥拍动作。

## F2 ONE CUE 系统

### 7.2.1 概念

`Cue` = 一条可执行的动作提醒，如"身体先走，手不要抢"。是整个产品闭环的锚点。

### 7.2.2 生命周期状态机

```
draft（草稿）
  → active（本周唯一生效）
  → done（已验证达标，进入历史）
  → archived（手动归档，不再出现）

同时最多 1 条 active。
```

### 7.2.3 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | ✅ | 自增/时间戳 |
| text | string | ✅ | Cue 文本 |
| skill | enum | ✅ | forehand_drive / backhand_drive / footwork / serve / receive / other |
| priority | int | ✅ | 1=最高，用于 Backlog 排序 |
| status | enum | ✅ | draft/active/done/archived |
| activeSince | date | 激活时 | 激活时间 |
| doneWeeks | int | — | 连续"改善"周数（用于完成判定） |

### 7.2.4 交互流程

**创建 Cue**
```
我的 → ONE CUE 管理 → 「+ 新建」
  → 输入 text（必填）
  → 选 skill
  → 选 priority
  → 保存 → 进入 Backlog
```

**激活**
```
Backlog 列表 → 某条 Cue → 「设为本周 Cue」
  → 若已有 active，旧 active 自动转 archived（提示"上一目标已归档"）
  → 新 Cue 转 active，记录 activeSince
```

**完成 / 归档**
- 自动完成：周末反馈（F8）判定达标后，Cue 从 active → done。
- 手动归档：active Cue 可「暂停并归档」。

### 7.2.5 Backlog 排序规则

- 默认按 `priority` 升序（1 排最前）。
- 支持上移/下移（改 priority）。
- Backlog 不设上限，但首页只提示"待处理 N 项"。

### 7.2.6 边界与异常

- 无任何 Cue 时，首页 Cue 卡显示引导文案"先记录一个想改的问题"。
- 删除 Cue 需二次确认；删除 active Cue 需先归档或设为 done。

### 7.2.7 验收标准

- 任意时刻 active 数量 ≤ 1。
- 激活新 Cue 后旧 Cue 自动归档，无数据丢失。
- 所有 Cue 可在历史中查看。

## F3 训练生成器（规则引擎）

见第 9 节完整算法。此处定义对外契约。

### 7.3.1 输入

```
{ scene, durationMin, cueId?, feeling }
```

### 7.3.2 输出

```jsonc
{
  "id": "plan_xxx",
  "scene": "metro_sit",
  "durationMin": 3,
  "cueText": "身体先走，手不要抢",
  "steps": [
    { "exerciseId": "shoulder_relax", "name": "肩胛放松", "durationSec": 30, "cue": "感受紧与松的区别" },
    { "exerciseId": "reaction_color", "name": "颜色反应", "durationSec": 60, "mode": "color" }
  ]
}
```

### 7.3.3 验收标准

- 输出 steps 总时长 ≈ durationMin（±15 秒内）。
- steps 中的 exercise 均满足该 scene 的约束。
- 传入 cueId 时，至少 1 步命中该 Cue 的 `cueMap`。

## F4 Random Reaction

### 7.4.1 功能描述

全屏随机显示刺激，训练"视觉刺激 → 动作选择"的快速映射。MVP **只做刺激展示 + 手动判断，不做自动判分统计**。

### 7.4.2 刺激模式（5 种）

| 模式 | 刺激内容 | 用户映射 |
| --- | --- | --- |
| `direction` | LEFT / RIGHT / ⬅️ / ➡️ | 左/右并步（脑内或实际） |
| `stroke` | FH / BH | 正手 / 反手 |
| `color` | 红/蓝/绿/黄 色块 | 用户自定义映射 |
| `number` | 1/2/3/4 | 用户自定义映射 |
| `dual` | 颜色 + 数字组合 | 组合映射（进阶） |

### 7.4.3 刺激参数（可配置）

| 参数 | 默认 | 范围 |
| --- | --- | --- |
| 刺激显示时长 | 500ms | 300 / 500 / 800 / 1000ms |
| 刺激间隔 | 随机 1～3s | 1～3s / 2～5s |
| 训练总时长 | 30s | 20 / 30 / 60s |
| 是否语音播报 | 关 | — |

### 7.4.4 Reaction Mapping（自定义映射）

用户可定义刺激 → 动作的映射，例如：

```
红 = 左并步
蓝 = 右并步
绿 = 正手
黄 = 反手
```

映射存入 `ttc:settings`。

### 7.4.5 双条件（dual）模式

屏幕同时出现「颜色 + 数字」，规则：

```
颜色 → 方向（左/右）
数字 → 击球（正手/反手）
组合 = 方向 + 击球，例如「红 3」→ 左移动 + 正手
```

### 7.4.6 交互细节

- 全屏刺激，字号/色块足够大（移动端 1m 外可辨）。
- 刺激区底部有「正确 / 跳过」两个大按钮（自评，不自动判分）。
- 计时到点自动结束，显示本轮完成次数。
- 顶部常驻当前 Cue 提示条。

### 7.4.7 边界与异常

- 无自定义映射时用默认映射。
- 屏幕常亮（`wakeLock`，如浏览器支持）。

### 7.4.8 验收标准

- 5 种模式均可运行一轮完整训练。
- 刺激按配置的显示时长/间隔呈现。
- dual 模式两个维度都正确组合。

## F5 Audio Cue

### 7.5.1 功能描述

通勤不盯屏时，通过耳机语音随机播报指令，用户脑内判断或轻微手指输入。

### 7.5.2 词库

`左 / 右 / 正手 / 反手 / 短 / 长`，可配置是否含"短/长"（落点判断）。

### 7.5.3 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 播报间隔 | 随机 2～4s | 1～3 / 2～4 / 3～6s |
| 语速 | 1.0 | 0.8 / 1.0 / 1.2 |
| 重复次数 | 1 | 每词播 1～2 次 |
| 总时长 | 60s | 30 / 60 / 120s |

### 7.5.4 技术实现

- `SpeechSynthesis`（TTS）或预置音频。
- 锁屏/黑屏下尽量可用（受浏览器后台限制，降级为前台播报并提示）。

### 7.5.5 验收标准

- 语音按词库 + 间隔随机播报，无重复异常。
- 锁屏不可用时给出明确降级提示。

## F7 训练执行

### 7.7.1 用户流程

```
训练计划（steps 数组）
  → 逐 step 展示
      ├─ 顶部：当前 Cue 提示条（常驻）
      ├─ 中部：动作名 + 说明 + 该动作自己的 Cue + 常见错误
      ├─ 底部：倒计时（可 暂停 / 跳过 / 提前结束）
  → step 到时自动进入下一个
  → 全部完成 → 写 session 记录 → 回到首页显示"今日完成"
```

### 7.7.2 计时器

- 倒计时为主（显示剩余秒）。
- 按钮：暂停 ⏸ / 跳过 ⏭ / 结束 ✕。
- 结束时振动（若支持）。

### 7.7.3 每 step 展示内容

| 字段 | 来源 |
| --- | --- |
| 动作名 | 动作库 name |
| 说明 | 动作库 description |
| 本动作 Cue | 动作库 cue |
| 常见错误 | 动作库 commonMistakes |
| 安全提示 | 动作库 safety |

### 7.7.4 完成记录

结束时写 `ttc:sessions`，字段见第 10 节。

### 7.7.5 边界与异常

- 中途退出：已完成的 step 可选择性记录（默认记录为 `completed: false`）。
- 生成失败（无可用动作）：提示"该场景+时长暂无可用训练"。

### 7.7.6 验收标准

- 完整跑完一个计划，session 正确落库。
- 暂停/跳过/结束行为符合预期。

## F8 周末反馈

### 8.1 功能描述

周末打球后，只问一个问题：**本周 Cue 有没有迁移到真实击球。**

### 8.2 入口

- 首页周末态卡片（周六/周日显示"本周验证"入口）。
- `club` 场景选择后直接进入。

### 8.3 交互

```
显示本周 Cue
  → 展示一个"只观察这一个指标"的验证提示
     例："正手定点攻球 20 板，只观察：身体是否先启动"
  → 4 档结果：明显改善 / 略有改善 / 没有变化 / 更差
  → 可选 note
  → 提交 → 写 ttc:feedback
```

### 8.4 Cue 完成判定规则

- 结果 ∈ {明显改善, 略有改善}：`doneWeeks += 1`
- `doneWeeks ≥ 2`（连续 2 周改善）→ Cue 自动 `done`，提示"本周目标已达成，建议激活下一个"
- 结果 ∈ {没有变化}：保持 active，下周继续
- 结果 ∈ {更差}：保持 active，并提示检查训练负荷（feeling 为 tired 时自动降负荷）

### 8.5 边界与异常

- 无 active Cue 时，反馈页提示先设置本周 Cue。
- 同一周重复提交：允许覆盖，以最后一次为准。

### 8.6 验收标准

- 反馈正确写库。
- 连续 2 周改善自动完成 Cue 并提示。

## F9 数据持久化

### 9.1 存储层 API（封装）

```ts
storage.get<T>(key): T | null
storage.set(key, value): void
storage.remove(key): void
storage.export(): string   // 全量 JSON 导出
storage.clear(): void
storage.migrate(): void    // schema 版本升级
```

### 9.2 迁移策略

- `ttc:meta.schemaVersion` 记录版本。
- 启动时对比代码内置版本，逐版本执行 migrate。
- 未来从 localStorage 迁 IndexedDB/云端时，仅替换 storage 层实现。

### 9.3 验收标准

- 刷新页面数据不丢失。
- 导出 JSON 可再导入还原。

# 9. 训练生成器规则（算法级）

### 9.1 输入

```ts
{ scene, durationMin, cueId?, feeling }
```

### 9.2 算法步骤

```
Step 1 — 候选过滤
  候选 = 动作库.filter(exercise => exercise.scenes.includes(scene))
  若 scene 为 metro_sit/stand，额外排除 space>0 或 intensity=high 的动作

Step 2 — feeling 负荷调节
  feeling=good  → 不调整
  feeling=normal→ 不调整
  feeling=tired → 降低：排除 intensity=high；提高 relaxation/mobility 权重
                  （即把 relaxation/mobility 动作排序提前）

Step 3 — Cue 命中优先
  若 cueId 有效，找到该 Cue 的 cueMap
  候选内命中 cueMap 的动作 → 置顶（保证至少 1 步关联 Cue）

Step 4 — 时长填充
  目标秒 = durationMin * 60
  从排序后的候选中循环取动作（每动作取其 durationMin）
  累加直到 ≥ 目标秒；最后一步裁剪到目标秒（±15s 容差）
  最少保留 2 个动作，不足时允许超出目标

Step 5 — 输出 plan
  每 step：{ exerciseId, name, durationSec, cue, mode? }
```

### 9.3 示例输出

**地铁坐姿 3 分钟（cue=arm_stiff，feeling=normal）**

```
30s  肩胛放松（命中 arm_stiff，置顶）
60s  颜色反应
60s  动作想象（脑内：看到 FH → 准备→转体→击球→还原）
30s  Cue 回顾（"身体先走，手不要抢"）
```

**家 10 分钟（cue=hand_first，feeling=good）**

```
60s   准备姿态
120s  左右并步
120s  启动-制动
120s  随机步法
120s  Dead Bug
60s   慢速正手影子（命中 hand_first）
```

### 9.4 纯函数要求

- 无副作用，输入相同输出相同。
- 便于单元测试（可对每个 场景×时长×feeling 组合断言）。

# 13. 成功指标

第一版只验证：

> 工作日每天 5～10 分钟离台训练，能否让用户周末更快进入状态，并让某个具体技术问题连续几周改善。

观测指标：

- 训练规律性：每周完成天数 / 总天数
- Cue 改善：同一 Cue 连续 N 周反馈趋势
- 迁移效果：周末"明显/略有改善"占比

> 卡路里、步数、时长**不作为**核心指标。
