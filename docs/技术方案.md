## 5. 数据层设计（`lib/storage.ts`）

### 5.1 封装原则

- 所有 localStorage 访问收敛到 `storage` 单例，UI 层不直接碰 `localStorage`。
- 为未来迁 IndexedDB/云端预留替换点：只改 `storage` 实现，store 层无感。

```ts
const NS = 'ttc:';
const CURRENT_SCHEMA = 1;

export const storage = {
  get<T>(key: string): T | null {
    const raw = localStorage.getItem(NS + key);
    if (!raw) return null;
    try { return JSON.parse(raw) as T; } catch { return null; }
  },
  set(key: string, value: unknown): void {
    localStorage.setItem(NS + key, JSON.stringify(value));
  },
  remove(key: string): void {
    localStorage.removeItem(NS + key);
  },
  exportAll(): string {
    const data: Record<string, unknown> = {};
    for (let i = 0; i < localStorage.length; i++) {
      const k = localStorage.key(i)!;
      if (k.startsWith(NS)) data[k] = JSON.parse(localStorage.getItem(k) ?? 'null');
    }
    return JSON.stringify(data, null, 2);
  },
  clearAll(): void {
    const keys = Object.keys(localStorage).filter(k => k.startsWith(NS));
    keys.forEach(k => localStorage.removeItem(k));
  },
  migrate(): void {
    const meta = this.get<Meta>('meta');
    const v = meta?.schemaVersion ?? 0;
    if (v < 1) { /* 首个版本，无需迁移 */ }
    // 未来：if (v < 2) { ... 数据转换 ... }
    this.set('meta', { schemaVersion: CURRENT_SCHEMA, firstUseAt: meta?.firstUseAt ?? Date.now() });
  },
};
```

### 5.2 Key 一览

| Key | 内容 | 写入频率 |
| --- | --- | --- |
| `ttc:meta` | schemaVersion / firstUseAt | 低 |
| `ttc:cue` | `{ primary: Cue|null, backlog: Cue[], history: Cue[] }` | 低 |
| `ttc:settings` | Settings | 低 |
| `ttc:abilities` | Abilities | 低 |
| `ttc:sessions` | Session[]（追加，按 date 倒序） | 中 |
| `ttc:feedback` | Feedback[] | 低 |

### 5.3 容量与边界

- localStorage 典型 5MB，本 App 纯文本数据远达不到上限。
- `sessions` 数组增长缓慢（每天最多几次），无需分页/压缩。
- 若未来 sessions 过大，再切 IndexedDB（替换 storage 层即可）。

### 6.3 Cue 生命周期逻辑（`lib/cue.ts`，纯函数便于测试）

```ts
export function activateCue(cues: {primary, backlog, history}, id: string) {
  const next = { ...cues };
  if (cues.primary) next.history.push({ ...cues.primary, status: 'archived' });
  const idx = cues.backlog.findIndex(c => c.id === id);
  const cue = { ...cues.backlog[idx], status: 'active' as const, activeSince: today(), doneWeeks: 0 };
  next.backlog = cues.backlog.filter(c => c.id !== id);
  next.primary = cue;
  return next;
}

/** 周末反馈后判定：连续 2 周改善 → done */
export function applyFeedback(cues, feedback: Feedback): CueState {
  const cue = cues.primary;
  if (!cue) return cues;
  if (feedback.result === 'much' || feedback.result === 'slight') {
    cue.doneWeeks += 1;
    if (cue.doneWeeks >= 2) {
      cue.status = 'done';
      // 移入 history，清空 primary，提示激活下一个
    }
  }
  // none → 保持；worse → 保持并建议降负荷（由 UI 提示）
  return cues;
}
```

## 7. 训练生成器（`lib/generator.ts`，纯函数）

> 核心设计：**纯函数 + 依赖注入**（`exercises` 作为参数传入），保证可单测、输入相同输出相同。

```ts
export interface GenerateInput {
  scene: Scene;
  durationMin: number;
  cue: Cue | null;
  feeling: Feeling;
  exercises: Exercise[];
}

export function generatePlan(input: GenerateInput): TrainingPlan {
  const targetSec = input.durationMin * 60;
  let candidates = input.exercises.filter(e => e.scenes.includes(input.scene));

  // 1) 地铁约束：零空间、禁高强度
  if (input.scene === 'metro_sit' || input.scene === 'metro_stand') {
    candidates = candidates.filter(e => e.space === 0 && e.intensity !== 'high');
  }

  // 2) feeling=累：降负荷，放松/活动度优先
  if (input.feeling === 'tired') {
    candidates = candidates.filter(e => e.intensity !== 'high');
    candidates.sort((a, b) =>
      rank(a.ability) - rank(b.ability)); // relaxation/mobility → 0
  }

  // 3) Cue 命中置顶：保证至少一步关联当前问题
  if (input.cue?.tags.length) {
    const tags = new Set(input.cue.tags);
    candidates.sort((a, b) => {
      const ah = a.cueMap.some(t => tags.has(t)) ? 0 : 1;
      const bh = b.cueMap.some(t => tags.has(t)) ? 0 : 1;
      return ah - bh;
    });
  }

  // 4) 时长填充
  const steps: PlanStep[] = [];
  let acc = 0;
  for (const e of candidates) {
    if (acc >= targetSec) break;
    const remain = targetSec - acc;
    const sec = Math.min(e.durationMin * 60, remain);
    steps.push({ exerciseId: e.id, name: e.name, durationSec: sec, cue: e.cue, ...(e.mode ? { mode: e.mode } : {}) });
    acc += sec;
  }
  // 兜底：候选为空或不足时（理论上不会，metro 场景也有 reaction/relaxation 动作）

  return { id: genId('plan'), scene: input.scene, durationMin: input.durationMin, cueText: input.cue?.text, steps };
}
```

**测试要点**（`tests/generator.test.ts`）：
- 每种 场景×时长×feeling 组合输出非空且总时长 ±15s。
- metro 场景输出不含 `space>0` 或 `intensity=high`。
- 传 cue 时首步命中 `cue.tags`。
- 相同输入输出完全一致（纯函数）。

## 9. 反应训练引擎（`hooks/useReaction.ts`）

状态机：

```
idle → showing(刺激显示 displayMs) → gap(随机 gapRange) → showing → ...
       ↑                                                    ↓
       总时长到 → finished
```

```ts
type ReactionPhase = 'idle' | 'showing' | 'gap' | 'finished';

interface ReactionConfig {
  mode: ReactionMode;
  displayMs: number;
  gapRange: [number, number];
  durationSec: number;
  mapping?: Record<string, string>;
}

export function useReaction(cfg: ReactionConfig) {
  // 返回 { phase, stimulus, count, start, stop }
  // stimulus 生成：
  //   direction → 随机 LEFT/RIGHT/⬅️/➡️
  //   stroke    → FH/BH
  //   color     → 红/蓝/绿/黄（配合 mapping）
  //   number    → 1/2/3/4
  //   dual      → 颜色+数字组合（方向 + 击球）
  // 计时用 setTimeout 链（showing 结束→排 gap，gap 结束→排 showing），
  // 而非 setInterval，便于精确控制不同相位时长。
}
```

**要点**：
- 全屏刺激、大字号/大色块（1m 外可辨）。
- 底部「正确 / 跳过」两个大按钮（自评，MVP 不自动判分）。
- `useWakeLock` 保持屏幕常亮（`navigator.wakeLock.request('screen')`，不支持则静默降级）。

## 19. 工程化闭环开发环境（AI 友好自动化）

> 目标：让 Claude Code 自主完成「理解项目 → 改代码 → 编译 → 测试 → 启动 → 浏览器真实验证 → 发现问题 → 修复 → 再验证」的闭环。依据 `docs/ai-友好自动化工程要求.md`，落地到本项目。

### 19.1 环境基线（Stage 1）
- Node v22.20.0、pnpm 10.30（**不更换包管理器**）、git 2.53 均已就绪。
- 需新建：`package.json` + lockfile、`CLAUDE.md`、`.claude/`、`.github/workflows/`。

### 19.2 统一命令入口（Stage 2）
见 §15.1。核心契约：`verify = lint + typecheck + test + build`，本地与 CI 同一套标准。

### 19.3 CLAUDE.md（Stage 3）
根目录 `CLAUDE.md` 必须写明：项目架构 / 技术栈 / 目录结构 / 开发·编译·测试·验证命令 / 编码约束 / 修改原则 / Definition of Done。并强制两条：
- **任何代码修改完成后必须执行 `pnpm verify`。**
- **任何用户可见 Web UI 修改，都必须进行真实浏览器验证，不得仅根据代码推断 UI 工作正常。**

### 19.4 Playwright MCP（Stage 4）
- 检查是否已配置；未配置则**不擅自修改用户全局配置**，提示用户执行：`claude mcp add playwright npx @playwright/mcp@latest`。
- 若项目已提供可用 MCP，则复用。

### 19.5 Claude Skills（Stage 5）
- `.claude/skills/project-verify/SKILL.md`：lint/typecheck/test/build，失败定位根因并修复。
- `.claude/skills/run-webapp/SKILL.md`：启动 → 等 dev server ready → 找真实 URL → 确认 HTTP 可访问（**不得硬编码端口**）。
- `.claude/skills/verify-webapp/SKILL.md`：启动 → Playwright MCP 打开 → 验证本次改动用户流程 → 查 page/console/network error；失败继续修复。

### 19.6 Stop Hook（Stage 6）
- 用 `update-config` 配置 Stop Hook（优先简单、确定性的 command hook）。
- 目标：Claude 声明任务完成时检查 `verify` 是否成功；**代码有修改但验证失败，不允许当作成功完成**。

### 19.7 GitHub Actions（Stage 7）
- `.github/workflows/ci.yml`：checkout → setup Node → install frozen deps → `pnpm verify`。与本地完全一致，不允许两套标准。
- `.github/workflows/deploy.yml`：push 到 main 时 `pnpm build`（`base: '/TT-Companion/'`）→ `actions/configure-pages` → `actions/upload-pages-artifact` → `actions/deploy-pages`，发布到 GitHub Pages。

### 19.8 实际闭环测试（Stage 8）
- 依次跑 install / lint / typecheck / test / build / dev。
- Playwright MCP 真实访问：页面可打开、核心内容可渲染、一个主要交互流程可执行、无阻断性 browser error；失败继续修复。

### 19.9 最终交付报告
按 **PASS / FAIL / N/A** 输出 Environment / Commands / Claude Configuration / Validation；Manual Actions 只列 Claude 无法自行完成、确需用户手工执行的步骤（如 `claude mcp add playwright ...`）。
