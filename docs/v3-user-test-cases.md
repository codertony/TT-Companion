# V3 台上训练编排器 · 用户测试用例

> 版本：v1（对应 change `v3-table-training`）
> 编写视角：一个真实普通水平的业余球友（约 1000–1500 分，工作日离台练、周末 1–2 次上台）
> 结构：按「用户旅程」组织，从第一次打开到熟练使用
> 说明：**期望结果尽量落到具体 UI 文案或可见行为**，便于验证者据此判定通过/失败；对已实测发现与规格不一致的用例，额外标注 `⚠️ 实测差异`。

---

## 0. 怎么用这份文档

### 0.1 判定规则

- 每条用例的**验收标准**都是一句可判定真假的陈述。满足即为**通过**，不满足即为**失败**。
- 步骤中出现的引号文案（如 `今天降负荷练`）是**界面上应出现的原文**，验证时用肉眼或页面检索对照。
- 涉及时间/计时的用例，允许 ±1 分钟误差；涉及数值阈值的用例，按用例中给出的公式手算校验。

### 0.2 测试数据准备

| 目的 | 操作 |
| --- | --- |
| 全量重置 | 「我的 → 设置 → 清空全部数据 → 确认清空（不可恢复）」 |
| 造**绿态** Check-in | 首页点「今日还没 Check-in」→ 睡眠选 `≥8h`、感觉选 `精神好`、不选疼痛、不选症状 → 保存并返回 |
| 造**黄态** Check-in | 同上，但：睡眠 `≤5h` 或 `6–7h`，感觉选 `很累`，或勾选一个疼痛部位（如 `肩`） |
| 造**红态** Check-in | 同上，但在「是否有以下症状」中勾选 `胸痛` / `晕厥` / `异常气促` 任一 |
| 造 **ONE CUE** | 「我的 → ONE CUE 管理」新建并激活一条 |
| 造**下肢短板（limiter）** | 「我的 → 评估中心」做「单腿站平衡」，左右两次成绩相差 >25% |
| 直接改存储 | 浏览器 Local Storage 键位：`ttc:checkin`、`ttc:cue`、`ttc:assessments`、`ttc:tableSession`、`ttc:tableCheck` |

> 注意 1：Check-in 每天只保留一条（同日覆盖），跨天测试需重新 Check-in。
> 注意 2：地址栏是 Hash 路由（`#/`、`#/table`、`#/table/run`）。**只在 hash 之间跳转不会重新加载页面**，验证「刷新后」这类场景必须用浏览器刷新（F5）或重新输入地址，否则测试结论不成立。

### 0.3 本模块的入口与路由

| 路径 | 页面 | 进入方式 |
| --- | --- | --- |
| `#/` | 首页 | Tab「首页」 |
| `#/table` | 台上训练编排 | 首页「台上训练编排 →（周末上台）」 |
| `#/table/run` | 台上训练执行 | 编排页「生成训练课 →」 |
| `#/data` | 数据 | Tab「数据」 |

## 一、旅程 A：第一次打开（无 ONE CUE / 无评估数据）

### UC-01 首页第一次看到「台上训练编排」入口

- **用户情境**：周末到了球馆，想在手机上找「今天上台练什么」。
- **前置条件**：已清空全部数据；当天已做绿态 Check-in。
- **操作步骤**：
  1. 打开首页。
  2. 观察「开始训练 →」按钮下方。
- **期望结果**：看到与「开始训练 →」并列的入口文字 `台上训练编排 →（周末上台）`，位置在离台训练入口正下方、视觉上并列不冲突。
- **验收标准**：首页存在文案完全等于 `台上训练编排 →（周末上台）` 的入口，且点击后进入编排页（标题 `台上训练编排`）。

### UC-02 第一次进入编排页的默认值

- **用户情境**：昨晚临时决定明天去球馆，什么都没设置过就点进来了。
- **前置条件**：无 ONE CUE、无评估记录；当天绿态 Check-in。
- **操作步骤**：
  1. 从首页进入编排页。
  2. 不点任何选项，逐项观察默认选中项。
- **期望结果**：
  - 横幅为绿态文案 `今天适合上台训练`；
  - 目标技术默认选中 `正手攻`；
  - 球源默认选中 `球搭子`；
  - 球搭子水平默认选中 `水平一般`；
  - 时长默认选中 `90 分钟`；
  - 页面底部有「生成训练课 →」按钮且可点击。
- **验收标准**：上述 5 个默认选中项与横幅文案全部一致，页面无需任何输入即可直接生成训练课。

### UC-03 没有 ONE CUE、没有评估数据时的「今天台上重点」

- **用户情境**：第一次用，既没定过本周 CUE，也没做过身体评估，想知道 App 会怎么安排。
- **前置条件**：无 ONE CUE、无评估记录（评估中心一条都没做）。
- **操作步骤**：
  1. 进入编排页。
  2. 读「今天台上重点（由 ONE CUE / 短板推导）」卡片。
- **期望结果（按规格）**：因为是「无 CUE 且无短板」的空白状态，卡片应显示 `正手攻`，理由为 `尚未设置 ONE CUE 或短板，从基础正手攻开始`。
- **⚠️ 实测差异**：实际显示的是 `步法稳定`，理由是 `下肢稳定为当前短板，优先练固定移动（两点正手）`。原因是「未评估」也被 Limiter 引擎当作候选短板（`unknown` 状态参与排序），因此 `deriveTableFocus` 里那条空白兜底文案在真实流程中**不会出现**。
- **验收标准**：卡片显示的重点技术、理由与规格一致（当前实现：**失败**，详见风险点 R2）。

### UC-04 采纳系统推荐的重点技术

- **用户情境**：不懂「今天台上重点」是怎么来的，但愿意听 App 的。
- **前置条件**：任意状态，只要「今天台上重点」的目标技术与当前选中的「目标技术」不一致。
- **操作步骤**：
  1. 观察重点卡片下方是否出现按钮。
  2. 点击 `就用「___」`。
  3. 观察「目标技术」区域的选中态与下方「进阶链」。
- **期望结果**：重点卡片出现按钮 `就用「{重点标题}」`；点击后该技术对应的按钮变为蓝底白字（选中态），且「进阶链」立即刷新为新技术的 A–G 七步。
- **验收标准**：点击后选中态转移 + 进阶链首行名称包含新技术名（例如 `两点正手·固定`）；当重点技术与已选目标技术相同时，该按钮不出现。

### UC-05 没做今日 Check-in 就直接进编排页

- **用户情境**：急着出门，跳过了 Check-in 直接点台上训练。
- **前置条件**：当天**没有** Check-in 记录。
- **操作步骤**：
  1. 不清空 Check-in，直接进入编排页。
  2. 观察顶部横幅与生成按钮。
- **期望结果**：按当前规则，无 Check-in 时按 `{}` 评估，视为绿态，因此横幅显示 `今天适合上台训练`，「生成训练课 →」可点。编排页**不应**因为缺 Check-in 而阻断，但用户无从知道「今天的状态判断其实没做过」。
- **验收标准**：页面不阻断、横幅为 `今天适合上台训练`、按钮可点击并成功生成课表。
- **补充观察（体验缺口）**：编排页没有像首页那样提供「今日还没 Check-in →」的引导入口，用户在这里看不到「先做 20 秒 Check-in」的提示（详见 R13）。

### UC-06 第一次遇到看不懂的术语

- **用户情境**：进阶链里写着「Falkenberg」「前后板组合」，听到过但不知道具体是什么。
- **前置条件**：任意。
- **操作步骤**：
  1. 进入编排页，滑到底部。
  2. 点击 `术语说明`。
  3. 查找 `Falkenberg`、`发抢`、`前三板`、`追身`、`半出台`。
- **期望结果**：折叠区展开后，每个术语一行，格式为「术语：一句话解释」，至少包含
  `Falkenberg：经典脚步练习：反手 → 侧身正手 → 扑正手 → 回反手`、
  `发抢：发球抢攻：发球后，第三板主动起板抢攻`、
  `前三板：发球、接发球、第三板这三个环节`、
  `追身：球直奔身体（尤其肘部），是最难处理的位置`、
  `半出台：球落点靠近底线、部分出台的来球`。
- **验收标准**：展开后可见 25 条术语，且上述 5 个术语的解释文字完全一致。

## 二、旅程 B：周末上台规划

### UC-07 切换目标技术，进阶链随之刷新

- **用户情境**：这周想专门练反手起下旋。
- **前置条件**：已进入编排页。
- **操作步骤**：
  1. 在「目标技术」中点 `反手起下旋`。
  2. 观察「进阶链（技术 × 落点 × 移动 × 旋转 × 随机度 × 前后板）」。
- **期望结果**：进阶链为 7 步，级别依次为 A→G，名称分别为
  `反手起下旋·固定` / `反手起下旋·提高质量` / `反手起下旋·两落点` / `反手起下旋·半随机` / `反手起下旋·随机` / `反手起下旋·前后板组合` / `反手起下旋·比赛迁移`，
  每步下方一行规则说明（如 A 的规则为 `反手起下旋固定位置、固定速度、固定旋转`）。
- **验收标准**：进阶链首行 `A` + `反手起下旋·固定`，末行 `G` + `反手起下旋·比赛迁移`，且 7 行顺序为固定 → 提高质量 → 两落点 → 半随机 → 随机 → 前后板组合 → 比赛迁移（不允许从随机开始）。

### UC-08 球源 = 球搭子 + 水平一般（降难度）

- **用户情境**：周末约到的是水平一般的朋友，他挡不稳、控不住落点。
- **前置条件**：目标技术 `正手攻`，球源选 `球搭子`。
- **操作步骤**：
  1. 球搭子水平选 `水平一般`。
  2. 读「双方任务」卡片。
- **期望结果**：卡片标题为 `双方任务（正手攻 · L1）`，正文为
  `（降难度）落点放宽到半台、高弧线稳定连续、先上旋后下旋；原规则：A 正手斜线 ↔ B 正手斜线`，
  搭档行以 `（不要求落点精确/速度/复杂旋转）` 结尾。
- **验收标准**：正文以 `（降难度）` 开头，且同时出现「落点放宽到半台」「高弧线」「先上旋后下旋」三项降难度措施。

### UC-09 球源 = 球搭子 + 水平更高（只给我 70% 质量）

- **用户情境**：这次约到的是比我强很多的球友，怕他全力把我打得到处救球。
- **前置条件**：目标技术 `正手攻`，球源 `球搭子`。
- **操作步骤**：
  1. 球搭子水平选 `水平更高`。
  2. 读「双方任务」卡片。
- **期望结果**：正文恢复为原始规则 `A 正手斜线 ↔ B 正手斜线`（不再带降难度前缀），搭档行末尾出现 `（请先给我 70% 质量）`。
- **验收标准**：搭档任务行文字为 `B 正手斜线稳定回球（请先给我 70% 质量）`，且正文中不再出现「降难度」。

### UC-10 球源 = 发球机（适用层提示）

- **用户情境**：球搭子没约到，球馆只有一台发球机。
- **前置条件**：目标技术 `两点正手`（对应套路层 L3）。
- **操作步骤**：
  1. 球源切到 `发球机`。
  2. 观察页面变化。
- **期望结果**：
  - 「球搭子水平」整段**消失**（因为不适用）；
  - 出现「发球机提示」卡片，列出 `发球机适合本层：固定动作、固定步法、半随机`；
  - 「球搭子协议（8 条）」段落消失。
- **验收标准**：页面不再出现 `球搭子水平` 与 `球搭子协议` 字样，且「发球机提示」下出现文字 `发球机适合本层：固定动作、固定步法、半随机`。

### UC-11 球源 = 发球机 + 发抢（L6 不适用 + 抗提前移动）

- **用户情境**：想用发球机练发抢前三板。
- **前置条件**：目标技术选 `发抢`（对应套路层 L6，随机度「半随机」）。
- **操作步骤**：
  1. 球源切到 `发球机`。
  2. 读「发球机提示」的两条内容。
- **期望结果**：「发球机提示」应出现两条：
  - `发球机对 L5–L7 效果有限，建议改用球搭子`（明确告知不适用，并给出替代方案）；
  - `随机训练加入位置随机、深浅随机、频率轻微随机，避免提前移动`（对抗「知道下一球会来」）。
- **验收标准**：两条文案均出现，即使用户已选发球机，系统仍如实提示「效果有限、建议改用球搭子」而不是静默放行。

### UC-12 球源 = 多球（下旋起板进阶）

- **用户情境**：找了个队友帮我喂多球，主要想练下旋起板。
- **前置条件**：任意目标技术。
- **操作步骤**：
  1. 球源切到 `多球`。
  2. 读「多球下旋起板进阶」卡片。
- **期望结果**：卡片显示进阶链 `固定下旋 → 正手拉 → 下旋深浅变化 → 正反手随机`。
- **验收标准**：该文案完整出现，顺序与上述一致。

### UC-13 时长选择与课表时长分配

- **用户情境**：这次只有一小时，或者周末时间宽裕想练满两小时。
- **前置条件**：绿态 Check-in；任意目标技术与球源。
- **操作步骤**：
  1. 分别选 `60 分钟` / `90 分钟` / `120 分钟`，各生成一次训练课。
  2. 对每次课表，逐段记录段名与分钟数并求和。
- **期望结果**：
  - 每次都是 8 段，顺序为
    `身体+空挥热身 → 正手/反手基本球 → 当天核心动作 → 固定移动 → 半随机 → 发接发/前三板 → 随机/开放球 → 条件比赛/比赛`；
  - 各段分钟数之和**精确等于**所选总时长；
  - 参考分配：60 → `5/5/8/8/8/8/5/13`；90 → `8/8/12/12/12/12/8/18`；120 → `11/11/16/16/16/16/11/23`。
- **验收标准**：三个时长各自的段数均为 8、段序一致、分钟数合计与所选时长完全相等（尾段承担舍入差）。

### UC-14 球搭子协议我能不能看全

- **用户情境**：想照着协议跟朋友说清楚「谁练什么」。
- **前置条件**：球源 = `球搭子`。
- **操作步骤**：
  1. 找到「球搭子协议（8 条）」卡片。
  2. 尝试展开/滚动查看全部 8 条。
- **期望结果（按规格）**：8 条规则都可查看，包含 `每轮约 3–6 分钟换人` 与 `最后一定进入开放球`。
- **⚠️ 实测差异**：卡片只列出前 4 条并以省略号截断，**没有任何展开入口**，第 5–8 条（含「一次只增加一个难度」「练球目标和比赛目标不同」「最后一定进入开放球」）在 UI 中不可见。
- **验收标准**：能够看到全部 8 条协议文字（当前实现：**失败**，详见风险点 R14）。

### UC-15 安全门绿态：正常生成训练课

- **用户情境**：睡得好、精神好，周末想认真练一场。
- **前置条件**：当天 Check-in 绿态（睡眠 ≥8h、精神好、无疼痛、无症状）。
- **操作步骤**：
  1. 首页确认横幅 `今天适合训练`。
  2. 进入编排页，确认横幅 `今天适合上台训练`。
  3. 点击「生成训练课 →」。
- **期望结果**：跳转到执行页，标题为 `台上训练 · {目标技术}`，副行为 `{时长} 分钟 · 球源 {球搭子|发球机|多球} · 只注意「{关注点}」`；课表 8 段且最后一段为 `条件比赛/比赛`。
- **验收标准**：执行页出现且课表包含 `条件比赛/比赛` 段；总时长与所选一致。

### UC-16 安全门黄态：降负荷，没有比赛段

- **用户情境**：昨晚只睡了 5 小时而且肩有点酸，但还是想去球馆摸一摸球。
- **前置条件**：当天 Check-in 黄态（例：睡眠 `≤5h`、感觉 `很累`、勾选 `肩`）。
- **操作步骤**：
  1. 观察首页横幅与编排页横幅。
  2. 点击「生成训练课 →」。
  3. 逐段走完课表，记录段名与时长。
- **期望结果**：
  - 首页与编排页横幅均为 `今天降负荷练`，并显示原因 `疲劳 8/10；睡眠 5h；疼痛：肩`（示例）；
  - 生成按钮仍为 `生成训练课 →`（可点，**不阻断**）；
  - 课表为 **7 段**，**不含** `条件比赛/比赛`；
  - `随机/开放球` 时长降为正常值的一半（90 分钟场景下为 4 分钟，正常为 8 分钟）。
- **验收标准**：段数为 7、段名列表中无 `条件比赛/比赛`、`随机/开放球` 段时长 = 同参数绿态的一半（±1 分钟）。

### UC-17 安全门红态（路径一）：首页还能不能找到入口

- **用户情境**：今天胸口有点闷，本来不该练，但想看看 App 怎么说。
- **前置条件**：当天 Check-in 红态（勾选 `胸痛`）。
- **操作步骤**：
  1. 回到首页。
  2. 寻找「台上训练编排 →（周末上台）」入口。
- **期望结果（按规格）**：不生成台上训练课，并提示先休息；入口本身仍可被发现，点进去后能看到「今天先休息，不生成训练课」的原因说明。
- **⚠️ 实测差异**：首页在红态下**整块替换**为 `今天先休息，不做训练` + `出现警示症状：胸痛`，`台上训练编排 →（周末上台）` 入口**完全不显示**。用户会以为这个功能消失了。
- **验收标准**：红态下用户能从常规路径获知「台上训练今日不可用及原因」（当前实现：入口消失，**失败**，详见风险点 R1）。

### UC-18 安全门红态（路径二）：地址栏直连编排页

- **用户情境**：昨天把编排页加了书签，今天直接点书签进来。

  2. 观察横幅、按钮状态。
  3. 尝试点击生成按钮。
- **期望结果**：
  - 横幅为红态文案 `今天先休息，不生成训练课`，并显示原因 `出现警示症状：胸痛`；
  - 底部按钮文案变为 `今日先休息`，且为**禁用（灰化不可点）**状态；
  - 页面不跳转、不生成课表；

- **验收标准**：横幅文案正确 + 按钮文案为 `今日先休息` 且点击无任何跳转与课表生成。

### UC-19 训练配比（五类占比）能不能看到

- **用户情境**：想知道一场课里「练动作」和「打比赛」各占多少，好判断自己是不是练得太随意。
- **前置条件**：任意可生成状态。
- **操作步骤**：

  2. 生成训练课后，在执行页自上而下浏览全部内容。

- **期望结果（按规格）**：能看到五类配比（固定动作 / 固定脚步 / 半随机 / 发接发前三板 / 完全随机与比赛），当前默认约为 `30% / 25% / 20% / 15% / 10%`，并能看到配比随稳定性提升而变化的说明。
- **⚠️ 实测差异**：编排页与执行页**均无任何配比数字、条形图或说明文字**；配比只存在于内部计划对象里，用户完全看不到。
- **验收标准**：生成训练课后页面上出现五类配比的数值或图示（当前实现：**失败**，详见风险点 R3）。

## 三、旅程 C：训练执行

### UC-20 逐段倒计时与「完成此段」

- **用户情境**：站在球台边，一手拿拍一手拿手机，需要一眼看清现在该练什么、还剩几分钟。
- **前置条件**：已生成训练课，停在执行页第 1 段。
- **操作步骤**：
  1. 观察第 1 段界面。
  2. 等待 5 秒观察倒计时是否在走。
  3. 点击 `完成此段`。
- **期望结果**：
  - 页面显示当前段名（如 `身体+空挥热身`）、`约 8 分钟`、大字倒计时 `8:00` 逐渐减少；
  - 顶部有进度条与 `段 1/8`，右侧显示 `下一段：正手/反手基本球`；
  - 点击 `完成此段` 后立即切到第 2 段，倒计时重置为第 2 段的时长，`段 2/8`，`下一段` 更新。
- **验收标准**：倒计时按秒递减；每点一次 `完成此段` 段号 +1、段名与倒计时同步替换；到第 8 段时 `下一段：自检`。

### UC-21 暂停与继续

- **用户情境**：练到一半球滚远了，去捡球，不想让计时白跑。
- **前置条件**：执行页任意段落正在计时。
- **操作步骤**：
  1. 点击 `暂停`。
  2. 等 10 秒，观察倒计时。
  3. 点击 `继续`。
  4. 等 5 秒再观察。
- **期望结果**：点 `暂停` 后按钮文案变 `继续`，倒计时**停住不动**；点 `继续` 后从暂停处接着走，不重置、不跳变。
- **验收标准**：暂停 10 秒期间显示数字完全不变；继续后从暂停时的数字继续递减。

### UC-22 换人提醒（球搭子）

- **用户情境**：和球友轮流练，怕一个人连续练太久质量下降。
- **前置条件**：球源 = `球搭子`，已生成训练课。
- **操作步骤**：
  1. 观察执行页顶部副行下方。
  2. 练习过程中留意是否再次出现换人提醒。
- **期望结果**：出现一行提示 `每轮约 3–6 分钟换人，保持质量` 与一个 `换人` 按钮。
- **验收标准**：该提示在球搭子模式下可见，且文案与 `每轮约 3–6 分钟换人，保持质量` 完全一致。
- **⚠️ 实测差异（体验缺口）**：该提示只在页面顶部**静态显示一次**，不会随时间或段落触发；而课表里每段的实际时长是 5–23 分钟，与「3–6 分钟换人」自相矛盾。同时执行页也不显示每段该练哪条套路，用户仍需回想或翻回编排页（详见 R4、R19）。

### UC-23 换人提醒在发球机 / 多球下的表现

- **用户情境**：今天一个人用发球机练，本来就没有「换人」这回事。
- **前置条件**：球源分别选 `发球机`、`多球`，各生成一次。
- **操作步骤**：
  1. 进入执行页，搜索 `换人`。
- **期望结果**：**不出现** `每轮约 3–6 分钟换人` 提示与 `换人` 按钮（对单人球源不适用）。
- **验收标准**：发球机与多球两种球源的执行页均不含 `换人` 字样。

### UC-24 点「换人」按钮会发生什么

- **用户情境**：和球友打了一会儿，真的换人了，顺手点一下按钮记一笔。
- **前置条件**：球源 = `球搭子`，执行页第 1 段。
- **操作步骤**：
  1. 记住当前倒计时数字。
  2. 点击 `换人`。
  3. 观察按钮文案与倒计时。
- **期望结果**：按钮文案从 `换人` 变为 `已换人`，作为「本轮已完成换人」的记录反馈。
- **验收标准**：点击后按钮文案变为 `已换人`。
- **⚠️ 实测差异（体验缺口）**：点击后**倒计时不重置**（仍是原数字继续走），也没有次数计数、没有按段提示、无法看出本轮换人发生在哪一段。用户容易误以为点了就会开始新的一轮（详见 R4）。

### UC-25 黄态课表：段序与缺失段

- **用户情境**：今天状态差，App 说降负荷，我想知道到底减了什么。
- **前置条件**：黄态 Check-in，生成训练课。
- **操作步骤**：
  1. 逐段记录段名与时长，直到出现自检表单。
- **期望结果**：段序为 `身体+空挥热身 → 正手/反手基本球 → 当天核心动作 → 固定移动 → 半随机 → 发接发/前三板 → 随机/开放球`（7 段），条件比赛段被移除，`随机/开放球` 时长减半；所有段完成后直接进入自检表单。
- **验收标准**：7 段全部走完即可进入自检；过程中不出现 `条件比赛/比赛`。
- **⚠️ 实测差异（体验缺口）**：页面对「今天为什么没有比赛段」没有任何说明，用户可能以为是 App 出错或自己点错了（详见 R5）。

### UC-26 练到一半不想练了，中途退出

- **用户情境**：练到第 3 段，球馆要关门了，直接想走。
- **前置条件**：执行页第 3 段（未走完课表）。
- **操作步骤**：
  1. 点击右上角 `结束`。
  2. 回到首页后，进入数据页查看。
- **期望结果（按规格）**：应有一次确认（避免误触丢失整节课），并明确告知「这节课不会/会如何被记录」。
- **⚠️ 实测差异**：`结束` 是普通链接，**点击立即跳回首页，没有任何二次确认**；本次训练**不产生任何记录**（台上训练记录与自检记录都不会写入），用户也无从得知「这次白练了」。
- **验收标准**：中途退出前出现确认或明确的记录说明（当前实现：**失败**，详见风险点 R7）。

### UC-27 生成后刷新页面 / 切走再回来

- **用户情境**：练到第 2 段手机锁屏，解锁后浏览器把页面重载了。
- **前置条件**：已生成训练课，停在执行页。
- **操作步骤**：
  1. 在 `#/table/run` 页面按 F5 刷新。
  2. 观察页面内容。
  3. 点首页，查看是否有「继续上次训练」之类的恢复入口。
- **期望结果（按规格）**：台上训练课应被持久化（日期、目标技术、球源、套路段、完成情况），刷新或回来后可继续。
- **⚠️ 实测差异**：刷新后执行页显示 `还没有台上训练课` + `去编排`，整节课丢失；首页的「继续上次训练」入口只服务于离台训练，**台上训练没有任何恢复入口**，只能回编排页从第 1 段重来。
- **验收标准**：刷新后仍能继续未完成的台上训练课（当前实现：**失败**，详见风险点 R6）。

### UC-28 重复进入编排页并再次生成

- **用户情境**：上一节课练完了，隔天想再安排一次。
- **前置条件**：已完成过一次台上训练。
- **操作步骤**：
  1. 首页进入编排页。
  2. 换个目标技术与时长，再次点击「生成训练课 →」。
  3. 走完全部段并提交自检。
  4. 进入数据页查看「最近台上训练」。
- **期望结果**：可以反复生成，不受上一次影响；每次完成后在数据页新增一条记录，最新的排在最上面。
- **验收标准**：数据页「最近台上训练」出现两条记录，顺序为最新在前，且目标技术/球源/时长与各自生成时一致。

## 四、旅程 D：自我验收

### UC-29 五问自检「准·净·松·顺·回」

- **用户情境**：练完一场，脑子里只有「今天挺顺」这种模糊感觉，需要 App 逼我具体一点。
- **前置条件**：走完课表全部段，进入自检表单。
- **操作步骤**：
  1. 观察 `五问自检（准·净·松·顺·回）` 区域。
  2. 逐一点击 `准`、`净`、`松`、`顺`、`回`。
  3. 读下方的小字解释。
- **期望结果**：
  - 五个可点按钮，文案分别为 `准` `净` `松` `顺` `回`，默认均未选中；
  - 点击后变为绿底白字（选中态），再点可取消；
  - 下方一行解释：`准=球是否稳定落到目标区域 · 净=触球是否干净、稳定 · 松=是否在合理用力下完成，没越来越僵 · 顺=能否看清球、从容击球，不被节奏追 · 回=打完能否自然还原准备下一板`。
- **验收标准**：五个按钮文案与解释文字完全一致，且每个按钮可独立切换选中/未选中。
- **⚠️ 实测差异（体验缺口）**：规格要求每项记为「通过/警示/未过」三态，实际只有「选中/未选中」二态，粒度不足（详见 R8）。

### UC-30 六指标记录

- **用户情境**：想知道今天「上台率」到底是多少，而不是凭感觉。
- **前置条件**：自检表单。
- **操作步骤**：
  1. 观察 `六指标记录` 区域。
  2. 在六个输入框中依次填入：上台数 `18`、总数 `20`、最长连续 `12`、主观用力 RPE `4`、落点命中数 `15`、落点总数 `20`。
  3. 点击 `完成并记录`。
- **期望结果**：出现 6 个数字输入框，占位提示分别为 `上台数` `总数` `最长连续` `主观用力 RPE 1–10` `落点命中数` `落点总数`；移动端点击后弹出数字键盘；可正常提交。
- **验收标准**：6 个占位提示文案完全一致，输入与提交无报错，结果页出现「已存自检记录」。
- **⚠️ 实测差异（体验缺口）**：六个框**只有占位符、没有字段标签**，`总数` 是「总球数」还是「总组数」、`最长连续` 是板数还是分钟都不明确；`RPE` 未做解释；也没有输入校验（可填 0、可留空、可填「上台数 > 总数」而不被提示）（详见 R9）。

### UC-31 今天最常见失误（只选一个）

- **用户情境**：今天老是下网，想知道 App 有没有地方记下来。
- **前置条件**：自检表单。
- **操作步骤**：
  1. 找到 `今天最常见失误（只选一个）`。
  2. 点击 `下网`，再点击 `出界`，观察是否互斥。
- **期望结果**：7 个可选项 `下网` `出界` `板边` `来不及` `被顶` `站死` `还原慢`；任意时刻**只有一个**处于选中态；点击新项自动取消旧项。
- **验收标准**：选项文案与上述 7 项完全一致，且为单选互斥。

### UC-32 五问全过 → 建议进入下一级

- **用户情境**：今天五项感觉都很好，想知道能不能加难度。
- **前置条件**：自检表单；六指标填 上台数 `18`、总数 `20`、落点命中 `15`、落点总数 `20`、最常见失误选 `出界`。
- **操作步骤**：
  1. 勾选全部五项（准、净、松、顺、回）。
  2. 点击 `完成并记录`。
- **期望结果**：结果页显示 `训练课已记录`、`{时长} 分钟 · 8 段 · 已存自检记录`；「自我验收」卡片显示 `五问：✅ 全过`、`稳定性门槛：✅ 通过`，并给出提示 `五问全过，可尝试进入下一级（更难条件）`。
- **验收标准**：三项文案分别为 `五问：✅ 全过`、`稳定性门槛：✅ 通过`、`五问全过，可尝试进入下一级（更难条件）`。

### UC-33 五问部分通过 → 在当前难度巩固

- **用户情境**：今天有三项感觉不错，两项一般。
- **前置条件**：自检表单。
- **操作步骤**：
  1. 勾选 `准` `净` `松` 三项（共 3 项）。
  2. 提交。
- **期望结果**：结果页显示 `五问：⚠️ 部分通过`，提示文字为 `部分通过，继续在当前难度巩固`。
- **验收标准**：`五问：⚠️ 部分通过` 与 `部分通过，继续在当前难度巩固` 同时出现。

### UC-34 五问明显崩掉 → 建议退一级

- **用户情境**：今天状态很差，动作完全散掉。
- **前置条件**：自检表单。
- **操作步骤**：
  1. 只勾选 `准` `净` 两项（共 2 项）。
  2. 提交。
- **期望结果**：结果页显示 `五问：❌ 明显崩掉`，提示文字为 `五问明显崩掉，建议退一级，找当前最高可控难度`。
- **验收标准**：`五问：❌ 明显崩掉` 与 `五问明显崩掉，建议退一级，找当前最高可控难度` 同时出现（边界：勾选 3 项应判为 ⚠️，勾选 2 项应判为 ❌）。

### UC-35 稳定性门槛的判定是否可解释

- **用户情境**：想知道系统凭什么叫「通过」。
- **前置条件**：自检表单。
- **操作步骤**：
  1. 按 上台数 `10`、总数 `20`、落点命中 `15`、落点总数 `20`、失误选 `出界` 提交，记下结果。
  2. 重新生成并走完一次，按 上台数 `18`、总数 `20`、落点命中 `15`、落点总数 `20`、失误选 `出界` 提交，记账结果。
  3. 再重来一次，按 上台数 `18`、总数 `20`、落点命中 `15`、落点总数 `20`、失误选 `板边` 提交。
- **期望结果**：稳定性门槛 = 上台率 ≥85%（17/20 及以上）且 落点命中率 ≥70% 且 最常见失误不为 `板边`。因此：第 1 次 `— 未通过`；第 2 次 `✅ 通过`；第 3 次 `— 未通过`。
- **验收标准**：三次结果与上述规则完全一致（上台率 50% 不通过；85% + 落点 75% 通过；同样成功率但失误为板边则不通过）。
- **⚠️ 实测差异（体验缺口）**：结果页只显示 `稳定性门槛：✅ 通过 / — 未通过`，**不显示门槛的阈值与本次的实际数值**，用户无法自行核对，也无法知道「差多少」（详见 R12）。

### UC-36 忘记做自检就退出

- **用户情境**：练完最后一球，接了个电话就走了，手机锁屏前没点自检。
- **前置条件**：走完课表全部段，停在自检表单。
- **操作步骤**：
  1. 不填任何内容，直接点右上角 `结束`。
  2. 进入数据页查看。
- **期望结果（按规格）**：「忘记自检」不应让整节课消失——至少应留下「今天练了什么、但未做自检」的记录，并可在下次提醒补齐。
- **⚠️ 实测差异**：训练课记录与自检记录**都只在点击 `完成并记录` 时才写入**，因此直接退出后数据页没有任何痕迹，这节课等于没发生。用户会以为「只要练了就有记录」。
- **验收标准**：直接退出后数据页仍能看到本次训练（哪怕标注「未自检」）（当前实现：**失败**，详见 R7）。

### UC-37 空表单直接点「完成并记录」

- **用户情境**：想赶紧关掉页面，看到按钮就点了。
- **前置条件**：自检表单，五项未勾选、六指标留空、失误未选。
- **操作步骤**：
  1. 直接点击 `完成并记录`（不填任何内容）。
  2. 观察结果页。
- **期望结果（按规格）**：应提示「请至少完成五问自检 / 补全关键指标」并**留在表单**，避免把「什么都没填」误判为「练崩了」。
- **⚠️ 实测差异**：表单**无任何校验**，直接提交成功；由于五问全部未勾选 = 通过 0 项，结果页显示 `五问：❌ 明显崩掉` 与 `五问明显崩掉，建议退一级，找当前最高可控难度`。**系统会给用户一个与事实相反的结论**，且这条错误的自检记录已被写入。
- **验收标准**：空表单提交时出现校验提示且不写入记录（当前实现：**失败**，详见 R8）。

### UC-38 四道门槛 / Level A–G / 3 球诊断能不能查到

- **用户情境**：听说过「要过了四道门槛才算练好」，想看看 App 里怎么讲、自己在哪一级。
- **前置条件**：任意状态。
- **操作步骤**：
  1. 在编排页、执行页、自检页、结果页、数据页中检索 `稳定/质量/保持/迁移`「四道门槛」「Level A」「3 球诊断」「连续 3 次同类错误」「退一级」等关键词。
- **期望结果（按规格）**：四道进阶门槛（稳定性 / 质量 / 延迟保持 / 迁移）可查看其含义与阈值；Level A–G 的级别名称可见；3 球诊断法（连续 3 次同类错误才判为稳定问题、一次只调一个变量）有可读说明。
- **⚠️ 实测差异**：UI 中**只能看到「稳定性门槛」这一条的通过/未通过**，另外三道门槛（质量 / 延迟保持 / 迁移）、Level A–G 名称、3 球诊断法**全部没有入口**；进阶链上的 A–G 只是套路生成模板里的字母，不反映用户当前所处级别。
- **验收标准**：能在 App 内查到四道门槛、Level A–G 与 3 球诊断的说明（当前实现：**失败**，详见 R12）。

### UC-39 连续失误想主动退阶

- **用户情境**：练反手两落点时连续下网七八个，想降回固定位置先打稳。
- **前置条件**：执行页正在训练某一段。
- **操作步骤**：
  1. 在训练过程中寻找「降难度 / 退一级 / 换套路」之类的入口。
  2. 尝试只调整一个变量（如降低速度）以获得引导。
- **期望结果（按规格）**：系统应引导用户先统计同类错误、连续 3 次同类错误才诊断，并且**一次只调整一个变量**（击球时机 / 发力 / 来球 / 拍型中选一个），再打 10 球看错误是否减少；并提供「退回上一级」的明确动作。
- **⚠️ 实测差异**：执行页**只有计时器和「完成此段」**，没有任何纠错、诊断、退阶入口；「退一级」提示只在整节课全部结束、提交自检之后才出现一句话，此时已经无法在当次训练中执行。用户想中途降难度只能靠自己，App 帮不上。
- **验收标准**：训练过程中存在「退阶 / 一次只调一个变量」的引导入口（当前实现：**失败**，详见 R12）。

## 五、旅程 E：数据回看

### UC-40 数据页看到「最近台上训练」

- **用户情境**：想确认周末那场到底记上了没有。
- **前置条件**：已完成至少一次台上训练（走完全部段并提交自检）。
- **操作步骤**：
  1. 进入数据页。
  2. 向下滚动查看「最近台上训练」区域。
- **期望结果**：出现「最近台上训练」卡片，每条一行显示 `{目标技术} · {球源中文名}`，右侧显示 `{MM-DD} · {时长}min`（如 `正手攻 · 球搭子` / `09-22 · 90min`）；最多显示最近 5 条。
- **验收标准**：文案格式与上述一致，球源正确映射为 `球搭子`/`发球机`/`多球`。

### UC-41 台上训练算不算「今天练过了」

- **用户情境**：周末在球馆实打实练了两小时，想看看本周进度有没有涨。
- **前置条件**：**未完成**任何离台训练；已完成一次 90 分钟台上训练。
- **操作步骤**：
  1. 打开首页，读进度环与「本周已练 X 天 · 目标 7 天」。
  2. 进入数据页，读 `本周训练` / `连续打卡` / `累计训练` 三个统计卡。
- **期望结果（按常理与产品承诺）**：台上训练是「训练」，应计入本周训练天数与累计次数，或至少在界面上明确区分「离台」与「台上」两类进度。
- **⚠️ 实测差异**：首页显示 `0/7`、`本周已练 0 天`；数据页显示 `本周训练 0/7 天`、`连续打卡 0 天`、`累计训练 0 次`——而同一页的「最近台上训练」明明有记录。**用户练了两小时，进度仍是 0**，激励与信任双双断裂。
- **验收标准**：完成台上训练后，首页与数据页的训练进度有相应变化，或明确标注为「仅统计离台训练」（当前实现：**失败**，详见 R10）。

### UC-42 上周那场自检数据还能不能翻出来

- **用户情境**：想知道上次反手起下旋的上台率是多少，判断有没有进步。
- **前置条件**：已提交过至少一次自检（含六指标与五问）。
- **操作步骤**：
  1. 在数据页、「最近台上训练」卡片上尝试点击/展开某一条记录。
  2. 在全 App 检索六指标关键词（`上台数`、`最长连续`、`落点命中`、`RPE`、`准`、`净`）的历史展示。
- **期望结果（按规格）**：应能回看历史自检记录（六指标 + 五问 + 最常见失误 + 主注意点），否则用户无法判断是否满足「延迟保持 / 迁移」门槛，自我教练闭环断开。
- **⚠️ 实测差异**：六指标、五问、最常见失误、RPE 这些数据**只写不读**——除了结果页那一次瞬时展示，任何页面都查不到历史；「最近台上训练」卡片不可点击、无详情。
- **验收标准**：能查看历史自检记录的关键指标（当前实现：**失败**，详见 R11）。

### UC-43 「离台 → 球台」移动迁移闭环

- **用户情境**：工作日在家练步法和反应，周末上台验证到底有没有用。
- **前置条件**：本周已设置 ONE CUE；已完成过台上训练；**未**做过离台反应类专项。
- **操作步骤**：
  1. 进入「我的 → 周末验证」。
  2. 选择本周 CUE 的改善结果（如 `略有改善`）。
  3. 在 `移动迁移 · 两点步法（可选）` 中选择 `略有`，提交。
  4. 进入数据页，查看 `迁移线索（离台 → 球台）` 卡片。
- **期望结果**：数据页「迁移线索（离台 → 球台）」出现 `球台移动迁移：略有改善`，并显示说明 `离台指标与球台验证会逐步对齐；多记录几周后看趋势。`；该验证结果与离台指标出现在同一视图，可判断迁移是否发生。
- **验收标准**：提交移动迁移后，数据页迁移线索卡片出现 `球台移动迁移：略有改善`。

### UC-44 只练了台上、没练离台时的「迁移线索」卡片

- **用户情境**：这周只在周末上了台，工作日没做离台训练。
- **前置条件**：只有台上训练记录；无离台反应结果、无反应时、未提交过周末验证的移动迁移。
- **操作步骤**：
  1. 进入数据页。
  2. 检查是否存在 `迁移线索（离台 → 球台）` 卡片。
- **期望结果（按规格）**：台上训练已经产生「球台侧」数据，迁移视图应仍然存在，并引导用户「去『周末验证』记录移动迁移，才能看出离台训练有没有带到球台」。
- **⚠️ 实测差异**：该卡片只在「有离台反应正确率 **或** 有反应时 **或** 有移动迁移」时才渲染；只练台上的用户**整张卡片不出现**，反而是最需要看到引导的人看不到引导。同时「最近台上训练」与「迁移线索」是两张互不关联的卡片，谈不上「同一趋势视图」。
- **验收标准**：只完成台上训练时，数据页仍出现迁移线索模块及其引导文案（当前实现：**失败**，详见 R16）。

### UC-45 数据页空态

- **用户情境**：刚装好 App，还没练过任何东西。
- **前置条件**：清空全部数据。
- **操作步骤**：
  1. 进入数据页。
- **期望结果**：显示 `还没有训练数据`、`完成第一次训练后，这里会显示你的训练节奏和变化。`，以及一个 `开始训练` 按钮。
- **验收标准**：三段文案完全一致，按钮可点并进入离台训练流程。

## 六、旅程 F：熟练使用（有 CUE / 有评估数据的球友）

### UC-46 有 ONE CUE 时，台上重点是否跟着变

- **用户情境**：本周 CUE 定的是「身体先走」这类步法问题，希望台上重点跟着变。
- **前置条件**：已激活一条带步法/还原类标签的 CUE（如「还原太慢」「脚下跟不上」）；无下肢短板评估数据。
- **操作步骤**：
  1. 进入编排页，读「今天台上重点」卡片。
  2. 回到「ONE CUE 管理」换一条带发力/手抢类标签的 CUE（如「手臂先动」），再回编排页。
  3. 再换成带时机类标签的 CUE（如「起下旋抢点」），再回编排页。
- **期望结果**：三次应分别得到
  - 步法类 → 重点 `固定移动`（目标技术 `两点正手`）；
  - 发力/手抢类 → 重点 `正手攻`（目标技术 `正手攻`）；
  - 时机类 → 重点 `反手起下旋`（目标技术 `反手起下旋`）；
  且理由文字中应引用当前 CUE 的原文（如 `本周 CUE「身体先走」指向步法/还原，练两点移动`）。
- **验收标准**：三次重点标题与目标技术随 CUE 标签正确切换，且理由中出现了当前 CUE 的文本。

### UC-47 有下肢短板时优先步法稳定

- **用户情境**：上周在评估中心测出单腿站左右差得比较多。
- **前置条件**：评估中心「单腿站平衡」左右成绩相差 >25%（派生为 below 短板）；可无 CUE。
- **操作步骤**：
  1. 进入编排页，读「今天台上重点」。
- **期望结果**：重点显示 `步法稳定`，理由为 `下肢稳定为当前短板，优先练固定移动（两点正手）`；且**优先于** CUE 推导的结果（即同时存在 CUE 时，仍先给出步法稳定）。
- **验收标准**：重点标题为 `步法稳定`、理由文案一致；在同时设置发力类 CUE 的情况下仍返回 `步法稳定`。

### UC-48 换目标技术，双方任务与进阶链同步变化

- **用户情境**：这周想练发抢，看看 App 给的双方任务是不是实战化的。
- **前置条件**：球源 `球搭子`、水平 `水平一般`。
- **操作步骤**：
  1. 目标技术选 `发抢`，读「双方任务」卡片与「进阶链」。
  2. 目标技术选 `两点正手`，再读这两处。
- **期望结果**：
  - `发抢` → 卡片标题 `双方任务（发抢 1 · L6）`，规则为 `A 发下旋短球 → B 搓长反手 → A 反手起板 → 自由`，关注点 `搓长→起板→连续`；进阶链 7 步以 `发抢·固定` 开头。
  - `两点正手` → 卡片标题 `双方任务（两点正手 · L3）`，规则为 `中路 → 正手位 → 中路 → 正手位，全部正手`，关注点 `到位再打`。
- **验收标准**：两次的卡片标题、规则、关注点与上表完全一致，且标题中的层号分别为 L6 与 L3。

### UC-49 中途换球搭子（水平一般 → 水平更高）

- **用户情境**：本来约的是水平一般的朋友，来了个更强的球友顶替。
- **前置条件**：球源 `球搭子`、水平 `水平一般`、目标技术 `正手攻`。
- **操作步骤**：
  1. 记下当前「双方任务」的规则与搭档任务。
  2. 把球搭子水平改为 `水平更高`。
  3. 再次读「双方任务」。
- **期望结果**：规则从带 `（降难度）` 前缀的版本切换回原始规则 `A 正手斜线 ↔ B 正手斜线`；搭档任务从 `（不要求落点精确/速度/复杂旋转）` 变为 `（请先给我 70% 质量）`。
- **验收标准**：两处文案按上述规则完整切换，且切换是即时的（无需刷新页面）。

### UC-50 连续两个周末使用（记录累积与进阶线索）

- **用户情境**：上周练了正手攻，这周想继续，看看有没有累积。
- **前置条件**：上周已完成一次正手攻的台上训练；本周再次进入。
- **操作步骤**：
  1. 本周再生成一次同样目标技术的课，走完并提交自检。
  2. 进入数据页查看「最近台上训练」。
  3. 检查页面是否给出「和上次相比」的变化（上台率、五问、失误分类的变化趋势）。
- **期望结果（按规格）**：自我教练闭环应能支持判断「延迟保持（隔次不热身仍达标）」与「迁移」，因此至少应能对比两次同类训练的关键指标。
- **⚠️ 实测差异**：「最近台上训练」只罗列 `目标技术 · 球源 · 日期 · 时长`，**不含任何质量指标**，也没有对比或趋势；用户无法判断自己是否在进步，进阶只能凭感觉。
- **验收标准**：存在跨次同类训练的质量对比或趋势（当前实现：**失败**，详见 R11）。

## 七、边界与异常

### UC-51 只有 45 分钟的空档

- **用户情境**：球馆只订到 45 分钟，或者只想趁午休练一小会儿。
- **前置条件**：任意可生成状态。
- **操作步骤**：
  1. 在「时长」区域寻找 45 分钟或自定义时长的选项。
- **期望结果（按规格）**：规格只承诺 90–120 分钟的课表结构，因此 45 分钟不是硬需求；但产品层面应能处理「时间不足一次完整课」的真实场景（例如提示「时间不足，建议只做热身→核心动作→固定移动」）。
- **⚠️ 实测差异**：时长**仅有三档 60 / 90 / 120 分钟**，无自定义、无「时间不够」的替代方案；用户遇到 45 分钟时只能选 60 分钟然后中途 `结束`（而中途结束不产生任何记录，见 UC-26）。
- **验收标准**：存在应对「不足一次完整课」的选项或明确提示（当前实现：**失败**，详见 R18）。

### UC-52 移动端触控与桌面布局

- **用户情境**：在球台边用一只手操作手机；回家后又想在电脑上翻看。
- **前置条件**：任意状态。
- **操作步骤**：
  1. 在移动端视口（宽 390px）下测量各主要可点元素的高度：目标技术按钮、球源按钮、球搭子水平按钮、时长按钮、五问按钮、失误按钮、`完成此段`、`生成训练课 →`。
  2. 在桌面端视口（宽 1440px）打开首页、编排页、执行页、数据页。
- **期望结果**：所有主要触控目标高度 ≥ 48px（失误按钮为 44px 属于已知例外，应记录）；桌面端内容为单列居中、最大宽度 480px，不出现横向滚动。
- **验收标准**：所有列举的按钮高度 ≥48px（`失误` 类按钮若为 44px 需登记为例外）；桌面端四个页面均无横向滚动条且内容居中收窄。

### UC-53 深色模式

- **用户情境**：晚上在球馆，手机是深色模式。
- **前置条件**：任意状态。
- **操作步骤**：
  1. 「我的 → 设置 → 外观主题」切换 `深色`（或系统深色）。
  2. 依次查看编排页、执行页、自检表单、结果页、数据页。
- **期望结果**：五个页面在深色下文字对比度足够、无白底黑字残留、无不可读的浅灰字；红/黄/绿三态横幅在深色下仍可区分（红/黄/绿的底色与文字都切换为深色变体）。
- **验收标准**：五个页面均无「白底 + 浅色字」等不可读组合，三态横幅颜色可区分。

### UC-54 训练中途被打断（长时间离开）后再回来

- **用户情境**：练到第 5 段，被叫去接了个电话，20 分钟后回到页面。
- **前置条件**：执行页处于计时中的某一段（选一段时长较长的，如 18 分钟的条件比赛段）。
- **操作步骤**：
  1. 记录当前倒计时。
  2. 切到其他 App / 锁屏 2 分钟后回到浏览器（**不刷新**）。
  3. 观察倒计时与段号。
- **期望结果**：倒计时按真实经过时间继续（不因后台暂停而「白送」时间），回到页面后数字与真实时间一致；不会因为倒计时到 0 而**跳过**后续段落（即不会自动连跳多段）。
- **验收标准**：回到页面时显示的剩余时间与「离开时的剩余 − 实际离开时长」一致（误差 ≤5 秒），且段号未发生自动跳跃（仍是离开时那一段）。

## 八、易遗漏的风险点

> 下面这些是**需求/体验层面的缺口**，不是代码 bug。按「普通用户会不会被卡住」排序。

### R1 红态下首页把「台上训练」入口整个藏掉
红态时首页用 `今天先休息，不做训练` 整块替换了两个训练入口，`台上训练编排 →（周末上台）` **完全消失**；但地址栏直连 `#/table` 又能看到编排页和红态说明。**入口消失 ≠ 门禁生效**，反而让用户以为功能被删了，也让「为什么今天不能练」的解释无处可看。建议：入口保留但置灰，点进去显示红态原因与休息建议（编排页本来就已实现这套文案）。

### R2 第一次用就被判「下肢是短板」
没有任何评估数据时，`unknown` 状态同样会进入 Limiter 排序，于是新用户一进来就看到「下肢稳定为当前短板，优先练固定移动」——**依据是不存在的**。同时 `deriveTableFocus` 里那条为空白状态准备的兜底文案（`尚未设置 ONE CUE 或短板，从基础正手攻开始`）在真实流程中永远不会出现。建议：`unknown` 不应产出「短板」结论，或明确写成「尚未评估，先按基础技术开始」。

### R3 训练配比在 UI 里完全不可见
规格要求「配比可查看（固定动作/固定脚步/半随机/发接发前三板/完全随机与比赛，默认约 30%/25%/20%/15%/10%）」，但编排页和执行页都**没有任何配比数字或图示**。用户无法判断自己这周是不是「只练动作不打比赛」，也感知不到配比会随水平演进——这是整个方法论里最容易被忽略、却最影响长期效果的一环。

### R4 「每轮 3–6 分钟换人」与实际段落时长互相打架
执行页静态显示 `每轮约 3–6 分钟换人，保持质量`，但生成的每一段实际是 5–23 分钟（90 分钟场景下尾段 18 分钟）。用户照着提示 4 分钟换一次人，就永远走不完当前段；不照做又违反协议。且「换人」按钮点了只把文案变成「已换人」，**不重置计时、不计数、不跟段落联动**。建议：要么把协议改成「每段内按 3–6 分钟轮换，段落时长是总量」，要么让换人按钮真正驱动一个小轮计时器。

### R5 黄态悄悄删掉比赛段，一个字都不解释
黄态课表从 8 段变 7 段、`随机/开放球` 时长减半，而页面**没有任何「今天为什么没有比赛段」的说明**。用户前一天还是 8 段，今天变 7 段，最容易的结论是「App 出错了」。建议在课表上方说明「今日降负荷：已移除条件比赛段并缩短开放球」。

### R6 刷新/切后台就丢课，且没有恢复入口
台上训练课只存在于内存（持久化配置里只保留了历史 sessions），刷新即 `还没有台上训练课`。球馆里手机锁屏、切 App、误触返回都很常见。首页虽有一个「继续上次训练」，但它只服务于离台训练，台上训练**没有任何恢复路径**，用户只能从第 1 段重来。这是台上场景最致命的中断点。

### R7 训练课与自检记录「同生共死」
只有点 `完成并记录` 才会写入训练课记录与自检记录；中途点 `结束` 或练完忘记自检直接退出，**数据页一片空白**，用户以为白练了。而 `结束` 连二次确认都没有。建议：段落完成即落盘训练课记录（`completed: false`），自检单独补写，并允许事后补录。

### R8 五问自检是二态，且空提交会被判「崩掉」
规格要求每项记「通过/警示/未过」三态，实际只有「选中/未选中」。更严重的是**没有校验**：用户忘记点选直接提交 = 0 项通过 = `五问：❌ 明显崩掉，建议退一级`，系统给出一个与事实相反的结论，并且这条错误记录已经写进存储。建议：改成三态 + 提交前必填校验。

### R9 六指标只有占位符，没有标签、单位与校验
六个数字框只有 `上台数` `总数` `最长连续` `主观用力 RPE 1–10` `落点命中数` `落点总数` 这类占位提示：`总数` 是总球数还是总组数？`最长连续` 是板数？`RPE` 是什么？都没有解释。也没有校验（可填 0、可留空、可让「上台数 > 总数」）。用户要么乱填，要么干脆不填——而这两个数正是「稳定性门槛」的唯一输入。

### R10 台上训练不计入任何训练进度
完成一场 90 分钟台上训练后，首页仍是 `本周已练 0 天`、`0/7`，数据页仍是 `累计训练 0 次`——同一页的「最近台上训练」却有记录。用户会直接怀疑数据是不是丢了。至少应把台上训练单独统计并展示（如「本周台上训练 1 次 · 90 分钟」）。

### R11 自检数据只写不读
六指标、五问、最常见失误、RPE、主注意点，全部**只在结果页闪现一次**，之后任何页面都查不到；「最近台上训练」只有目标技术、球源、日期、时长。用户无法回答「上次上台率多少」「这类失误有没有变少」，自我教练闭环在「回看」这一环直接断掉。

### R12 四道门槛 / Level A–G / 3 球诊断都找不到入口
规格要求「不能仅凭连续板数进阶」，需要依次通过稳定性、质量、延迟保持、迁移四道门槛；UI 里**只有稳定性门槛**的通过/未通过，且不显示阈值与实际数值，另外三道门槛、Level A–G 名称、3 球诊断法（连续 3 次同类错误才诊断、一次只调一个变量）全都没有入口。用户「连续失误想中途退阶」时，App 一句话都不给；退阶提示只在整场结束、无法执行时才出现。

### R13 编排页没有「先做 Check-in」的引导
首页在没有 Check-in 时会引导用户去 Check-in，但编排页只是**静默按绿态处理**。用户直接进编排页时，既不知道今天的状态门没走过，也看不到入口——「20 秒判断今天能不能练」这个设计在台上流程里被绕开了。

### R14 球搭子协议只给看前 4 条
卡片写着「球搭子协议（8 条）」却只列前 4 条并以省略号截断，**没有展开入口**。被截掉的第 5–8 条恰恰是最影响训练质量的：「一次只增加一个难度」「练球目标和比赛目标不同」「最后一定进入开放球」。用户拿着手机想照着跟球友讲，讲不全。

### R15 术语表只在编排页底部，训练中查不到
25 条术语解释藏在编排页最底部的折叠区。可到了执行页、自检页，用户看到「Falkenberg」「追身」「半出台」时**没有任何查询入口**——而那正是他最需要看解释的时候（球台边、球搭子在等着）。建议执行页每段能就近展示该段的术语提示。

### R16 「离台 → 球台」迁移闭环在数据页被切断
「最近台上训练」与「迁移线索（离台 → 球台）」是两张互不关联的卡片；而迁移线索卡片只在有离台反应正确率 / 反应时 / 移动迁移时才渲染——**只练台上的用户根本看不到这张卡片和他的引导文案**（「去『周末验证』记录移动迁移」）。最需要被引导的人恰恰看不到引导，规格里的「同一趋势视图」也没有真正成立。

### R17 发球机提示会随目标技术突然变脸
提示按「代表套路所属层」给：选 `两点正手`（L3）得到「发球机适合本层」，选 `发抢`（L6）得到「发球机对 L5–L7 效果有限，建议改用球搭子」。逻辑是对的，但用户在已选发球机的前提下切换目标技术，提示会**突然翻转为「不适用」**，容易被当成 bug，也缺少「那我现在该怎么办」的替代路径（例如「L6 请改约球搭子」或「先用发球机练前 4 段，后 3 段改球搭子」）。

### R18 时长只有三档，且默认值与换人协议冲突
`60 / 90 / 120 分钟` 三选一，没有自定义，也没有「时间不够」的短课方案；球馆常见的 45 分钟、或「想练 150 分钟」都无处安放。默认 90 分钟又和「每轮 3–6 分钟换人」的提示相互矛盾。建议提供「我只有 45 分钟」的降级课表。

### R19 执行页只报段名，不报「这一段练什么」
执行页每段只显示一个抽象段名（`当天核心动作`、`半随机`），**不显示这一段具体该练哪条套路、规则是什么、唯一注意点是什么、搭档该做什么**。用户站在球台边想不起来「当天核心动作」到底指什么，只能翻回编排页找——而编排页此时已经被执行页顶掉了。台上训练最需要「一屏之内说清下一步做什么」。

### R20 红态空课表的原因文案可能是死代码
`buildTableSession` 在红态返回空课表并带原因 `今日状态不适合训练（出现警示症状），请先休息`，执行页也会渲染它；但编排页的生成按钮在红态已提前 `return`，用户实际永远走不到这个分支。将来若按 R1 放开红态入口，这段文案就会与红态横幅重复表达同一件事，需要一并整理。
